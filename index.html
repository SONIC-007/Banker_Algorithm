Understand the Basics

🏦

Banker's Algorithm

Developed by Edsger Dijkstra, this algorithm acts like a cautious banker — it only grants resources if doing so keeps the system in a safe state, guaranteeing all processes can eventually complete.

🔒

Deadlock

A deadlock occurs when processes wait for resources held by each other in a circular chain. No process can proceed, halting the system indefinitely. The Banker's Algorithm prevents this.

✅

Safe State

A state is safe if at least one execution sequence (the safe sequence) exists in which every process can complete. The algorithm searches for this before granting any resource request.

📊

Need Matrix

Need[i][j] = Maximum[i][j] − Allocation[i][j]. Shows how many more resources each process might request. If Need ≤ Work, the process can run to completion.

🔢

Allocation Matrix

The number of resources currently held by each process. When a process finishes, its allocation is released back into the Available (Work) pool.

⚙️

Available Vector

Free instances of each resource type. After each process completes in the safe sequence, its Allocation is added back to the Work vector (available pool).

About This Simulator

This simulator demonstrates Banker's Algorithm for deadlock avoidance — one of the fundamental algorithms in Operating Systems, originally designed by Edsger W. Dijkstra.

Supports full matrix editing, step-by-step manual mode, auto-play, preloaded test cases, and a rich visual breakdown of every algorithm iteration including the Need vs Work comparison table.

📚 Help & Glossary

🏦 Banker's Algorithm

Before granting a resource request, the algorithm simulates the allocation and checks whether a safe sequence still exists. Only safe grants are permitted.

📌 Allocation Matrix

Allocation[i][j] = currently held instances of resource j by process i. Edit any cell directly in the Matrices tab.

📈 Maximum Matrix

Maximum[i][j] = maximum instances of resource j that process i may ever need. Must be ≥ Allocation for each entry.

🧮 Need Matrix (auto-computed)

Need = Maximum − Allocation. Updated live as you type. A process is eligible to run when Need[i] ≤ Work (available).

📦 Available / Work Vector

Free instances of each resource type. Grows when processes complete and release allocations.

⚠️ How to Use

1. Set process & resource counts → Generate Tables.
2. Fill Allocation, Maximum, Available.
3. Choose Manual or Auto mode.
4. Click "Run Banker's Algorithm".
5. Watch the Visualization tab — use "Next Step" in Manual mode.
